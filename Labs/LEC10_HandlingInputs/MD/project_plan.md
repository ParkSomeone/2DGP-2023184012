# 소년 이동 프로젝트 구현 계획

## 1. 프로젝트 개요

이 프로젝트는 Python과 pico2d를 사용하여 화면에서 소년 캐릭터를 키보드 입력으로 이동시키는 게임을 구현하는 것을 목표로 한다.

- 개발 언어: Python
- 사용 라이브러리: pico2d
- 대상 파일 위치: `Labs/LEC10_HandlingInputs/`
- 구현 파일: `move_character_with_key.py`
- 사용 자원: `animation_sheet.png`, `TUK_GROUND.png`

---

## 2. 목표

1. 방향키 입력을 감지한다.
2. 입력 상태에 따라 소년의 이동 방향을 결정한다.
3. 이동 중에는 애니메이션을 재생한다.
4. 방향키를 누르지 않으면 IDLE 상태 애니메이션을 출력한다.
5. 화면 경계를 벗어나지 않도록 소년의 위치를 제한한다.
6. ESC 키 또는 창 닫기 이벤트로 게임을 종료할 수 있게 한다.

---

## 3. 핵심 요구사항

### 3.0 스프라이트 애니메이션 명세

스프라이트 시트는 `animation_sheet.png`를 사용하며, 화면 출력 시 다음 규칙을 따른다.

- 한 프레임의 크기: 100x100
- 한 애니메이션당 프레임 수: 8프레임
- 프레임 순환 방식: `clip_draw(frame * 100, row * 100, 100, 100, x, y)`
- 스프라이트 시트 전체 크기: 800x400

애니메이션별 출력 위치:

- IDLE: 시작 위치=(0, 300), 마지막 위치=(700, 300), 프레임 수=8, 출력 크기=100x100
- MOVE_RIGHT: 시작 위치=(0, 200), 마지막 위치=(700, 200), 프레임 수=8, 출력 크기=100x100
- MOVE_LEFT: 시작 위치=(0, 100), 마지막 위치=(700, 100), 프레임 수=8, 출력 크기=100x100
- MOVE_UP: 시작 위치=(0, 0), 마지막 위치=(700, 0), 프레임 수=8, 출력 크기=100x100
- MOVE_DOWN: 시작 위치=(0, 300), 마지막 위치=(700, 300), 프레임 수=8, 출력 크기=100x100

이 좌표는 스프라이트 시트의 기준 위치이며, 실제 구현에서는 방향에 따라 해당 행을 선택하고 프레임을 순환하여 출력한다.

### 3.1 입력 처리
- `SDL_KEYDOWN`과 `SDL_KEYUP` 이벤트를 처리한다.
- 오른쪽/왼쪽/위/아래 방향키를 기준으로 이동 상태를 관리한다.
- `SDL_QUIT` 또는 `ESC` 입력 시 게임 루프를 종료한다.

### 3.2 이동 로직
- 방향키가 눌린 상태이면 해당 방향으로 소년을 이동시킨다.
- 키가 떼어지면 이동 상태를 해제한다.
- 이동 속도는 일정하게 유지한다.

### 3.3 애니메이션
- 상태에 따라 적절한 스프라이트 프레임을 선택한다.
- 이동 중에는 `RUN` 애니메이션을 재생한다.
- 정지 상태에는 `IDLE` 애니메이션을 출력한다.
- 프레임은 순환 구조로 반복 재생한다.

### 3.4 경계 처리
- 소년의 x, y 좌표가 화면 밖으로 나가지 않도록 제한한다.
- 왼쪽/오른쪽/위/아래 경계값을 기준으로 clamp 처리한다.

### 3.5 출력 구조
- 배경을 먼저 그린다.
- 소년을 마지막에 그린다.
- `clear_canvas()`, `update_canvas()`, `delay()`를 적절히 사용한다.

## 5. 구현 단계 계획

### 단계 1: 기본 캔버스 및 자원 로드
- `open_canvas()`를 호출한다.
- 배경 이미지와 캐릭터 스프라이트를 로드한다.
- 초기 위치와 상태 변수를 설정한다.

### 단계 2: 게임 루프 기본 구조 준비
- `running` 변수를 정의한다.
- `while running:` 루프를 작성한다.
- `clear_canvas()`, `update_canvas()`를 배치한다.

### 단계 3: 이벤트 처리 함수 작성
- `handle_events()`를 정의한다.
- `get_events()`로 이벤트 목록을 가져온다.
- `SDL_QUIT` 처리와 `ESC` 종료 처리를 추가한다.

### 단계 4: 키 입력 상태 관리
- `dir_x`, `dir_y` 또는 이동 상태 변수를 추가한다.
- 방향키 입력을 누르면 상태값을 증가하거나 설정한다.
- 키를 떼면 상태값을 감소하거나 초기화한다.

### 단계 5: 이동 방향 결정
- 상태값을 기반으로 이동 벡터를 계산한다.
- 각 방향에 맞는 속도를 적용한다.

### 단계 6: 캐릭터 위치 갱신
- 이동 방향에 따라 x, y 좌표를 갱신한다.
- 좌표가 화면 경계를 넘지 않도록 보정한다.

### 단계 7: 스프라이트 프레임 변수 설정
- `frame` 변수를 추가한다.
- 프레임이 계속 증가하도록 반복 구조를 만든다.

### 단계 8: 정지 상태 애니메이션 처리
- 이동이 없을 때는 `IDLE` 프레임을 출력한다.
- `frame`을 적절히 순환시킨다.

### 단계 9: 이동 상태 애니메이션 처리
- 이동 중일 때 각 방향별로 다른 스프라이트 행을 선택한다.
- 방향에 따른 캐릭터 그림 위치를 조정한다.

### 단계 10: 배경과 캐릭터 출력 순서 정리
- 배경을 먼저 그린 뒤 소년을 출력한다.
- 전체 화면이 깔끔하게 보이도록 위치를 조정한다.

### 단계 11: 경계 제한 구현
- 좌표가 화면 바깥으로 나가지 않도록 `min`, `max` 계산을 적용한다.
- 소년이 화면을 벗어나지 않도록 보장한다.

### 단계 12: 방향별 애니메이션 분리
- 좌/우/상/하 이동에 따라 스프라이트 시트의 특정 영역을 선택한다.
- 각 방향마다 다른 프레임열을 사용한다.

### 단계 13: 디버깅 및 프레임 속도 조정
- 입력이 너무 민감하지 않은지 확인한다.
- 이동 속도와 애니메이션 속도를 조절한다.

### 단계 14: 종료 로직 검증
- `ESC`와 창 닫기 이벤트가 모두 정상적으로 종료되는지 확인한다.
- 게임 루프가 정상적으로 끝나는지 검사한다.

### 단계 15: 경계 조건 테스트
- 화면 가장자리에서 이동을 시도할 때 위치가 유지되는지 확인한다.
- 경계에서 멈추는 동작을 점검한다.

### 단계 16: 입력 중복 방지 검증
- 키를 누르고 있을 때 상태가 누적되지 않는지 확인한다.
- `KEYDOWN`/`KEYUP` 조합이 정상적으로 처리되는지 체크한다.

### 단계 17: 애니메이션 자연스러움 보정
- 프레임 간 전환이 부드럽게 이루어지도록 `delay()` 값을 조정한다.
- 정지 상태와 이동 상태 간 전환을 자연스럽게 만든다.

### 단계 18: 코드 정리
- 불필요한 테스트 코드와 임시 출력을 제거한다.
- 함수 역할이 명확하게 분리되도록 정리한다.

### 단계 19: 최종 동작 검증
- 방향키 이동 확인
- 정지 시 IDLE 확인
- 경계 제한 확인
- 종료 처리 확인

### 단계 20: 최종 커밋 및 정리
- 기능이 모두 동작하는지 최종 확인 후 커밋한다.
- 문서와 코드가 일관되도록 마무리한다.
