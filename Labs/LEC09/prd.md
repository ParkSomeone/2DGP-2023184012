# Sonic 스프라이트 애니메이션 뷰어 개발 PRD

## 1. 문서 목적

`pre_prd.md`의 요구사항을 구현 가능한 기능, 검증 기준, 단계별 개발 계획으로 구체화한다. 이 문서는 `Labs/LEC09`에서 실행할 단일 파일 애니메이션 뷰어의 기준 문서다.

## 2. 프로젝트 개요

- 프로젝트명: Sonic Sprite Animation Viewer
- 목적: 스프라이트 시트에 포함된 동작들을 순서대로 재생하고, 동작별 반복 및 대기 동작을 확인한다.
- 개발 언어: Python
- 그래픽 라이브러리: `pico2d`
- 실행 파일: `Labs/LEC09/sonic-sprite_animation_viewer.py`
- 입력 이미지: `Labs/LEC09/sonic-sprite.png`
- 배포 형태: 별도 모듈 분리 없이 실행 파일 하나로 구성한다. 이미지 파일은 실행 파일과 함께 둔다.

## 3. 목표와 범위

### 목표

1. 스프라이트 시트의 모든 애니메이션을 빠짐없이 재생한다.
2. 각 애니메이션을 5회 반복하고, 반복을 마친 뒤 1초 대기한다.
3. 대기 후 다음 애니메이션으로 넘어가며, 마지막 애니메이션 다음에는 처음부터 무한 반복한다.
4. 스프라이트가 화면에서 식별하기 쉬운 크기로 보이도록 확대해 출력한다.
5. 반복 횟수와 대기 시간을 프레임 수나 컴퓨터 성능에 좌우되지 않도록 시간 기준으로 관리한다.

### 범위에서 제외

- 스프라이트 시트 편집 기능
- 사용자 입력으로 애니메이션 선택 또는 재생 속도 변경
- 별도의 GUI 메뉴, 설정 저장, 오디오
- 단일 실행 파일 이외의 패키징 및 배포 작업

## 4. 사용자 시나리오

1. 사용자가 `sonic-sprite_animation_viewer.py`를 실행한다.
2. 뷰어 창이 열리고 첫 번째로 정의된 애니메이션이 화면 중앙에 표시된다.
3. 해당 애니메이션이 프레임 순서대로 재생되고, 한 사이클을 완료할 때마다 반복 횟수가 증가한다.
4. 5회 재생이 끝나면 화면을 유지한 채 1초간 대기한다.
5. 다음 애니메이션이 같은 방식으로 재생된다.
6. 마지막 동작의 대기가 끝나면 첫 번째 동작으로 돌아가 과정을 계속한다.
7. 사용자가 창 닫기 이벤트를 보내면 뷰어가 정상 종료한다.

## 5. 기능 요구사항

### FR-01. 스프라이트 시트 로드

- `pico2d`로 `Labs/LEC09/sonic-sprite.png`를 연다.
- 이미지 경로는 실행 작업 디렉터리에 따라 달라지지 않도록 스크립트 파일 위치를 기준으로 결정한다.
- 이미지 로드에 실패하면 원인을 알 수 있도록 오류를 표시하고 비정상적인 후속 렌더링을 중단한다.

### FR-02. 애니메이션 및 프레임 데이터

- 스프라이트 시트의 모든 동작을 애니메이션 목록으로 명시한다.
- 각 애니메이션은 프레임의 원본 이미지 영역과 프레임 수를 알 수 있는 데이터로 정의한다.
- 프레임의 가로 폭이 서로 다를 수 있으므로 고정 폭 분할을 전제로 하지 않는다. 실제 이미지 분석 결과에 따라 프레임별 영역을 정의한다.
- 애니메이션 재생 순서는 데이터 목록에 선언된 순서로 한다.
- 시트의 행·영역 구분, 좌표, 프레임 수는 이미지 확인을 통해 확정하고 추측값을 최종 데이터로 사용하지 않는다.

### FR-03. 프레임 재생

- 현재 애니메이션의 프레임을 순서대로 출력한다.
- 마지막 프레임 다음에는 해당 애니메이션의 첫 프레임으로 순환한다.
- 프레임 변경은 경과 시간으로 판정한다. 렌더링 루프의 반복 횟수 자체를 재생 속도로 사용하지 않는다.
- 프레임 간격은 코드에서 명확히 관리하고, 전체 동작을 눈으로 확인해 적절한 값으로 확정한다.

### FR-04. 반복 및 대기

- 애니메이션의 전체 프레임 순환을 1회 재생 완료로 계산한다.
- 현재 애니메이션이 5회 완료되면 프레임 변경을 멈추고 1초 동안 대기한다.
- 대기 중에는 현재 프레임을 유지한다.
- 대기 종료 시 다음 애니메이션으로 전환하고 프레임 및 반복 상태를 초기화한다.
- 마지막 애니메이션 이후에는 첫 애니메이션으로 순환한다.

### FR-05. 화면 출력

- 애니메이션은 창 안에서 눈에 띄도록 확대해 출력한다.
- 원본 비율을 유지하고 창 경계를 넘지 않게 출력 크기를 정한다.
- 같은 애니메이션 안에서는 프레임별 원본 크기 차이로 캐릭터가 갑자기 커지거나 작아 보이지 않도록 출력 기준을 일관되게 적용한다.
- 캐릭터의 기준 위치는 창 중앙으로 한다.
- 창 크기와 출력 배율의 초기값은 실제 시트의 크기와 실행 결과를 확인해 확정한다.

### FR-06. 이벤트 및 종료

- 메인 루프에서 `pico2d` 이벤트를 처리한다.
- 창 닫기 이벤트를 받으면 루프를 종료하고 사용한 그래픽 자원을 정리한다.
- 명시되지 않은 키보드 조작은 추가하지 않는다.

## 6. 비기능 요구사항

- 실행 파일은 `sonic-sprite_animation_viewer.py` 하나로 유지한다.
- Python과 `pico2d` 외의 추가 라이브러리를 도입하지 않는다.
- 애니메이션 프레임 데이터, 재생 상태 갱신, 이벤트 처리, 렌더링의 역할을 함수 단위로 구분하되 여러 파일로 분리하지 않는다.
- 재생 상태는 프레임 인덱스, 현재 애니메이션 인덱스, 반복 완료 횟수, 마지막 프레임 변경 시각, 대기 시작 시각으로 추적한다.
- 최종 코드에는 단계 검증용 임시 출력문을 남기지 않는다.

## 7. 상태 전이

| 현재 상태                   | 조건                              | 처리                                   | 다음 상태       |
| --------------------------- | --------------------------------- | -------------------------------------- | --------------- |

| 애니메이션 재생             | 마지막 프레임 완료, 반복 횟수 1~4 | 첫 프레임으로 이동, 반복 횟수 증가     | 애니메이션 재생 |

| 마지막 애니메이션 대기 완료 | 다음 항목 없음                    | 첫 애니메이션 선택                     | 애니메이션 재생 |
| 모든 상태                   | 창 닫기 이벤트                    | 루프 종료 및 자원 정리                 | 종료            |

## 8. 완료 및 검증 기준

- 프로그램을 실행하면 지정된 PNG를 로드하고 창을 연다.
- 시트에서 확인된 모든 애니메이션이 선언된 순서대로 출력된다.
- 프레임은 각 애니메이션의 프레임 수에 맞게 순환하며, 애니메이션 경계에서 잘못된 프레임을 참조하지 않는다.
- 각 애니메이션은 정확히 5사이클 재생되고 이후 1초간 프레임이 유지된다.
- 각 애니메이션을 5사이클 재생하고 마지막 프레임을 1초간 유지한 뒤 다음 애니메이션으로 넘어간다. 마지막 애니메이션의 대기가 끝나면 첫 번째 애니메이션으로 돌아가며, 이 순서를 창이 닫힐 때까지 반복한다.
- 캐릭터는 화면 중앙에 표시되고, 비율이 유지되며 창 밖으로 잘리지 않는다.
- 창 닫기 이벤트로 정상 종료한다.
- 코드에 구현 확인용 임시 출력문이 남지 않는다.

## 9. 사전 확인 항목 및 가정

`sonic-sprite.png`와 실행 결과를 확인해 다음 값을 확정했다.

- 시트 크기: 399×525 픽셀
- 재생 순서: 시트의 위에서 아래 순서로 정의한 10개 동작
- 동작별 프레임 수: 11, 12, 6, 9, 6, 6, 6, 8, 8, 4 (총 76프레임)
- 프레임 경계: 투명 픽셀 기준으로 확인한 각 프레임의 실제 사각형 좌표를 사용한다.
- 창 크기: 800×600 픽셀
- 프레임 간격: 0.1초
- 출력 배율: 동작별 최대 프레임 크기를 기준으로 산정해 동작 안에서 일정하게 유지한다.
- 스프라이트 시트에 동작 이름이 표시되어 있지 않아 `동작 1`부터 `동작 10`으로 구분한다.

## 10. 단계별 개발 및 커밋 계획

요구사항에 따라 전체 구현을 한 번에 작성하지 않는다. 아래 24개 단계를 각각 작게 구현하고, 단계별 동작을 확인한 뒤 의미 있는 변경 단위로 커밋한다. 각 커밋은 해당 단계의 완료 조건을 만족해야 한다.

| 단계 | 구현 내용                                         | 단계 검증                                 |
| ---: | ------------------------------------------------- | ----------------------------------------- |
|    1 | LEC09 실행 파일 생성 및 목적 주석/파일 구조 설정  | Python 구문 검사 통과                     |
|    2 | `pico2d` import 및 최소 실행 진입점 구성        | 모듈 import 및 실행 확인                  |
|    3 | 창 열기와 종료 처리 뼈대 구성                     | 창이 열리고 닫힘                          |
|    4 | 스크립트 기준으로 PNG 경로 계산                   | 다른 작업 디렉터리에서도 이미지 경로 확인 |
|    5 | 스프라이트 시트 로드 및 로드 실패 처리            | 지정 이미지 표시 또는 명확한 오류         |
|    6 | 이미지 원본 크기 및 시트 경계 확인 도구/절차 준비 | 시트의 실제 크기 확인                     |
|    7 | 동작별 영역과 프레임 경계 목록화                  | 모든 동작 영역과 좌표를 대조              |
|    8 | 하나의 애니메이션 프레임 데이터 정의              | 프레임 영역이 원본 시트와 일치            |
|    9 | 나머지 모든 애니메이션 데이터 정의                | 시트의 모든 동작 포함 여부 확인           |
|   10 | 애니메이션 목록과 재생 순서 정의                  | 목록 순서와 요구된 동작 순서 대조         |
|   11 | 현재 애니메이션·프레임 상태 변수 구성            | 초기 상태 값 확인                         |
|   12 | 경과 시간 기반 프레임 간격 처리                   | 지정 간격 전후 프레임 변경 확인           |
|   13 | 현재 프레임 원본 영역 렌더링                      | 각 프레임이 올바르게 잘려 출력            |
|   14 | 애니메이션 마지막 프레임 순환 처리                | 끝 프레임 다음에 첫 프레임 출력           |
|   15 | 전체 사이클 완료 횟수 계산                        | 프레임 수와 관계없이 1사이클당 1회 증가   |
|   16 | 5회 완료 후 대기 상태 전환                        | 5번째 사이클 이후 정지 상태 진입          |
|   17 | 1초 대기 시간 처리                                | 1초 전 유지, 1초 후 전환 허용             |
|   18 | 다음 애니메이션 전환 및 상태 초기화               | 프레임·반복 횟수 초기화 확인             |
|   19 | 마지막 애니메이션에서 첫 애니메이션 순환          | 전체 목록 반복 확인                       |
|   20 | 창 크기에 맞춘 비율 유지 확대 계산                | 경계 안 출력 및 비율 유지 확인            |
|   21 | 중앙 정렬 및 애니메이션 내 출력 크기 안정화       | 중앙 배치와 크기 변화 확인                |
|   22 | 전체 애니메이션 목록 연속 재생 통합               | 전체 순서·5회 반복·대기 통합 확인       |
|   23 | 창 닫기 이벤트와 자원 정리 검증                   | 실행 중 정상 종료 확인                    |
|   24 | 임시 출력 제거, 전체 회귀 확인 및 문서 정리       | 완료 기준 전체 통과 후 최종 커밋          |

### 커밋 원칙

- 각 단계 검증을 통과한 코드만 커밋한다.
- 커밋 메시지는 한국어로 작성하고, 해당 단계에서 실제로 완료한 내용을 설명한다.
- 여러 단계를 한 커밋으로 뭉치지 않고, 최소 20개 이상의 단계별 커밋을 남긴다.
- 실패한 단계는 원인을 수정하고 같은 검증을 다시 통과한 뒤 다음 단계로 진행한다.

## 11. 완료 정의

모든 기능 요구사항과 완료 기준을 만족하고, 24단계 개발 기록 및 최소 20개의 단계별 커밋이 확인되며, 실행 중 이미지 로드·애니메이션 전환·창 종료 오류가 없으면 개발 완료로 판단한다.
